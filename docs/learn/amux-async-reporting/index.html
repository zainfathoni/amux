Mailbox, bukan CCTV (arsip)

Penjelasan desain completion reporting Amux lama. Bukan dokumentasi command yang masih didukung.

Secara historis, Amux memisahkan durable mailbox untuk hasil dari doorbell murah untuk membangunkan coordinator. Pola ini tetap berguna untuk dipelajari, tetapi implementasi worker/report/callback Amux sudah tidak aktif.

Status: removed. Command worker, group, report, callback, deadline, dan finish telah dihapus—bukan sekadar deprecated. Jangan jalankan syntax lama atau mengubah store historisnya. Untuk work Amp baru gunakan native child creation, parent/reply routing, authenticated messaging, dan waiting. /amux-tycho adalah bridge receipt terpisah dan explicit-only untuk executor eksternal.

Lalu apa bedanya dengan /amux-tycho?

Karena Mas pembuat Tycho, framing yang paling tepat: /amux-tycho bukan orchestrator pengganti Tycho. Ia adalah adapter delivery di sisi Amp yang menerapkan ide serupa untuk hasil dari exact Tycho route, dengan boundary lebih ketat. Tycho tetap bebas mengorkestrasi provider di dalam domainnya, tetapi pada boundary ini Tycho hanya menjadi producer dengan authority report_only; Amp thread asli tetap coordinator, consumer, dan acknowledger.

Boundary Tycho: skill source saat ini↗

Kenapa receipt bridge lebih kompleks? Bukan karena kami tidak mempercayai orchestration internal Tycho, tetapi karena boundary lintas sistem butuh bukti delivery sendiri. Kami mengikat origin Amp, exact Tycho route, dan digest task/artifact agar process exit atau prose dari log tidak disalahartikan sebagai report untuk request yang salah.

Seam yang ingin kami capai bersama Tycho

Idealnya, satu request Amp ke exact Tycho route mengembalikan tepat satu object terautentikasi pada turn yang sama: status, summary, findings, blockers, dan verification. Object itu harus correlated ke Amp thread/request dan task/artifact identity; tanpa fallback, transcript mining, side inbox, atau automatic retry. Kalau field run membuktikan seam ini, receipt + consume + acknowledge compatibility bridge tidak perlu dibuat untuk work baru.

Status saat ini: desain lama sudah dihapus

Kami belajar bahwa mailbox + doorbell adalah pola yang benar. Tetapi native Amp kini sudah punya parent/child association, authenticated messaging, reply routing, dan waiting. Karena itu Amux tidak membuat database bayangan baru untuk child baru, dan command koordinasi lamanya sudah dihapus.

KasusmuPilihan sekarang
Agent dan subagent sama-sama native AmpPakai native child creation + reply routing/waiting. Jangan onboard ke group/report Amux baru.
Sudah punya durable group/report Amux lamaPertahankan bytes sebagai evidence inert. Jangan memakai binary lama, mengedit store, acknowledge, authorize-finish, atau membuat terminal transition.
Executor eksternal melalui Tycho/amux-tycho bisa dipakai secara explicit-only dan conditional; Tycho hanya mengirim typed report.
Orchestrator buatan sendiriAmbil kontraknya: durable report + cheap wake-up + idempotency + coordinator-owned verification. Tidak harus mengadopsi seluruh Amux.

Arah aktif: ADR 0009↗

Cold-recall defense, satu napas:
“Secara historis Amux memisahkan durable truth dari wake-up. Mekanisme worker/group/report/callback itu sekarang sudah dihapus; contoh ini hanya menjelaskan desain lama dan tidak mengizinkan drain atau mutation.”

Jawaban yang bisa langsung dikirim ke temanmu

“Iya, Mas—secara pattern ini problem yang dahulu kami pecahkan di Amux: durable result dipisahkan dari wake-up. Implementasi worker/group/report/callback itu sekarang historical-only dan tidak boleh dijalankan atau di-drain; native Amp menangani koordinasi Amp-to-Amp baru.

Di /amux-tycho, kami adaptasi pattern itu untuk output dari Tycho. Bukan mengganti orchestration Tycho: Tycho tetap mengatur agent/provider-nya, sedangkan boundary ke Amp hanya memberi Tycho authority report_only. Receipt mengikat Amp origin, exact Tycho route, dan task/artifact digest; hanya typed complete/blocked submit yang dianggap hasil—bukan process exit atau log.

Nuansanya, /amux-tycho adalah bridge terpisah yang masih experimental. Target akhirnya justru lebih simpel: exact Tycho route return satu structured result langsung ke invoking Amp turn, authenticated dan correlated. Kalau seam itu terbukti, side receipt/consume/ack tidak diperlukan untuk work baru. Group/report core Amux lama tetap inert dan dipertahankan tanpa mutation.”

Cek pemahaman

1. Callback gagal tepat setelah report berhasil disimpan. Apa sumber kebenarannya?
2. Tycho process exit tanpa structured submit berarti apa?
3. Untuk work Amp-to-Amp baru, jalur default saat ini apa?

Primary source

Baca ADR 0009 untuk arah saat ini: native Amp menangani koordinasi work baru, Amux tetap meluncurkan runner lokal, dan store koordinasi lama inert tanpa command drain. ADR 0007 tetap sebagai sejarah keputusan yang sudah dipersempit.
