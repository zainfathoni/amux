amux

Automatic machine-local Amp runners, bound to exact workdirs and launched through tmux.

Amux is active. It owns the local runner registry, launch, process lifecycle, diagnostics, and maintenance. Native Amp owns threads and task coordination.

What it does

Exact workdir bindingsEach runner is identified by its canonical existing directory and grouped in a named tmux workspace.
Stable native runner IDsOptionally pass --runner-id (-i) so every launch uses the same Amp runner ID.
Safe local lifecycleList, launch, park, restart, diagnose, unpin, or tear down only runners whose exact ownership can be proved.
Automatic recoveryLaunch all configured runners at login or boot, with separate scheduled Amp maintenance.

Install or update

Requires the Amp CLI and tmux. The release installer supports Linux and macOS and installs to ~/.local/bin/amux.

curl -fsSL https://amux.zainf.dev/install.sh | sh
amux version
amux install doctor
amux update

To pin a published version, set AMUX_VERSION. Homebrew users should let Homebrew own updates:

curl -fsSL https://amux.zainf.dev/install.sh | AMUX_VERSION=v0.6.0 sh

# Or use Homebrew
brew install zainfathoni/tap/amux
brew upgrade amux

amux update intentionally refuses executables owned by Homebrew, mise, asdf, Nix, or a system package manager. Use that manager’s update command instead.

Pin this runner and launch it

cd ~/Code/amux-runner
amux runner pin --workspace amux --current-dir --runner-id macbook-amux
amux runner launch --current-dir
amux runner doctor --current-dir

The shorter equivalents are -w, -c, and -i. After a command, --current-dir or -c means the command’s current directory—exactly --workdir .. It does not use the current tmux pane. The older --current selector keeps its tmux-based meaning.

Compatibility caveat: before the command name, -c <path> still means global --config-dir <path>. Prefer the long spelling in scripts: amux --config-dir ~/.config/amux-alt runner list --all.

Change a pinned native runner ID

amux --dry-run runner pin -w amux -d ~/Code/amux-runner \
  -i macbook-amux-new --restart
amux runner pin -w amux -d ~/Code/amux-runner \
  -i macbook-amux-new --restart

Changing the ID of a stopped runner updates its binding but leaves it stopped. Repeating the same ID is a no-op. A live ID change requires --restart; Amux first verifies the exact owned tmux pane, Amp process, executable, arguments, and workdir, then replaces that local process. This is a safe local replacement, not a promise of uninterrupted execution for active remote threads.

Runner lifecycle

CommandBehavior
listShow configured runner bindings. Add --all, a workspace, or an exact workdir.
launchStart absent configured runners. Bare amux and amux launch --all launch every row.
parkStop an exact verified local runner while preserving its registry binding and remote thread state.
restartReplace a running verified local process in place without changing its binding.
doctorDiagnose workdir, tmux, process, runner-ID, and maintenance state without mutation.
unpinRemove one exact binding only after proving its local runner is absent. It never stops a process.
teardownStop one exact runner, remove its clean attached secondary Git worktree, and unpin it. The branch is preserved.
removeUnavailable by design: retains the row and fails closed because authoritative process/catalog absence cannot yet be proved.
reconcileKeeps present rows unchanged. A missing workdir is retained and rejected rather than interpreted as permission to delete.

Top-level list, launch, park, restart, remove, doctor, and reconcile are runner-only aliases. Use --json for a versioned result document and --dry-run to validate and plan without mutation.

Teardown a completed secondary worktree

amux --json --dry-run runner teardown --workdir <secondary-worktree>
amux --json runner teardown --workdir <secondary-worktree> \
  --confirm-plan <sha256>

The apply step requires the fresh state-bound digest from dry-run. Teardown rejects primary, detached, dirty, locked, prunable, symlinked, non-root, current-directory, ambiguous, or unreadable targets. It does not delete the branch or archive Amp threads.

Activation and maintenance

At graphical login or boot, systemd or launchd runs amux launch --all. Verified patterns are a systemd user service with Type=oneshot and RemainAfterExit=yes, or a RunAtLoad LaunchAgent with AbandonProcessGroup=true. The OS activates Amux and retains its process group; it does not replace Amux with direct runner supervision.

Scheduled maintenance is separate and short-lived. Install it with the ownership that matches how Amp is updated:

amux runner maintenance install --update-owner self
# Use external when another package manager owns Amp:
amux runner maintenance install --update-owner external

Legacy migration: deprecated, then removed

The old coordination model is not merely deprecated: its commands have been removed. Current Amux commands do not create, adopt, migrate, drain, rewrite, or delete its historical state.

Legacy behaviorStatusReplacement
Workers and generalized spawn/adoptionRemovedCreate native Amp threads on the exact intended Orb or live runner/workdir.
Groups, reports, callbacks, and deadlinesRemovedUse native parent/reply routing, authenticated messages, and waiting.
Shelve and unshelveRemovedUse native Amp archive state.
Worker teardown and finish authorizationRemovedManage native thread completion/archive separately; use runner teardown only for the local runner and worktree.

Historical worker, shelf, group, report, callback, operation, and spawn-assignment files are inert evidence. Leave them untouched. The separate /amux-tycho skill uses its own explicit-only receipt bridge; it is not the removed worker-report route.
