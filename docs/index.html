amux

Automatic machine-local Amp runners, bound to exact workdirs and launched through tmux.

Native Amp owns all new task coordination. Amux remains active as the thin runner host; it is not deprecated or archived.

Retained active layer

  • Machine-local runner registry and canonical-workdir bindings
  • Runner pin, list, launch, doctor, park, restart, teardown, remove, and fail-closed reconcile
  • Automatic amux launch --all at graphical login or boot
  • tmux and amp --no-tui process launch
  • Install, update, maintenance, diagnostics, systemd, and launchd integration

Removed coordination layer

Amux workers, generalized spawn/adoption, shelves, groups, worker reports, callbacks, deadlines, worker teardown, and finish authorization have been removed. Their historical stores are inert and remain untouched. The protected #360 inventory may inspect them read-only only after separate owner authorization.

/amux-tycho is separate: its receipt consume/acknowledge bridge is not the removed worker-report mechanism and remains under issue #328's replacement gate.

Install

curl -fsSL https://amux.zainf.dev/install.sh | sh
npx skills add zainfathoni/amux --skill amux --global

Pin this runner

amux runner pin --workspace amux --workdir ~/Code/amux-runner
amux runner launch --workdir ~/Code/amux-runner
amux runner doctor --all

Teardown one completed worktree

amux --json --dry-run runner teardown --workdir <path>
amux --json runner teardown --workdir <path> --confirm-plan <sha256>

The state-bound runner command stops one exact local runner, removes one clean attached secondary worktree, and unpins it. It preserves the branch and never archives Amp threads.

Activation

At login/boot, the service manager runs amux launch --all. Verified patterns are systemd Type=oneshot with RemainAfterExit=yes, and a RunAtLoad LaunchAgent with AbandonProcessGroup=true. The OS activates Amux and retains its process group; it does not replace Amux with direct runner supervision.

New tasks

Use authenticated native Amp create_thread on the exact intended Workspace Project/Orb or exact live runner/workdir. Keep native parent/reply routing only; create no Amux worker or coordination state.
