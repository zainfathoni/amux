Amux is active as the local runner host. Native Amp owns threads, delegation, replies, waiting, and archive state.

canonical workdirs

Every runner binding resolves an existing directory to its canonical path. After a command, --current-dir or -c means --workdir .

native runner IDs

Pin --runner-id or -i to launch the same native Amp runner ID every time. The ID is launch configuration, not an Amux selector.

safe ID changes

Use --dry-run to preview changes. A stopped runner stays stopped; the same ID is a no-op; a live change requires --restart and exact ownership proof.

launch · park · restart

Launch starts an absent configured runner. Park stops an exact owned process but keeps its binding. Restart replaces a verified running process in place.

doctor · JSON · dry-run

Diagnose without mutation. Use --json for versioned results and --dry-run for validated mutation plans.

unpin

Remove one exact binding only after proving its local runner is absent. Unpin never stops a process and never changes remote Amp threads.

state-bound teardown

Stop one exact runner, remove one clean attached secondary Git worktree, and unpin it using a fresh plan digest. The branch and Amp threads remain.

fail-closed retention

remove is unavailable by design. Missing-workdir reconcile also rejects and retains the row rather than treating absence as deletion permission.

activation · maintenance

Launch every configured runner at login or boot, and schedule short-lived Amp maintenance separately with explicit update ownership.

Deprecated, then removed.

Amux itself is active. Its former coordination model is not: the old commands below have been removed, and current Amux does not create, adopt, migrate, drain, rewrite, or delete their historical state.

workers · spawn · adoption

Removed. Create native Amp threads on the exact intended Orb or live runner/workdir.

groups · reports · callbacks

Removed. Use native parent/reply routing, authenticated messages, waiting, and native dependency relationships.

shelves · deadlines

Removed. Use native Amp archive state and native coordination rather than Amux lifecycle records.

worker teardown · finish

Removed. Manage native thread completion and archive separately. Current runner teardown is local runner/worktree cleanup only.

historical stores

Worker, shelf, group, report, callback, operation, and spawn-assignment files are inert evidence. Leave them untouched.

/amux-tycho

The explicit-only Tycho receipt bridge is separate from the removed worker-report route and is never selected implicitly.

A runner skill for native Amp.

The bundled /amux skill operates the retained runner host and routes delegated work through native Amp. Provider skills are separate, experimental, explicit-only installs; the core skill defaults to native Amp.

$ npx skills add zainfathoni/amux --skill amux --global

See the skill guide and trigger reference.

“Pin this runner”amux runner pin -w … -c [-i …]
“Restore my workspace”amux launch --workspace …
“Park this runner”amux runner park --current-dir
“Restart this runner”amux runner restart --current-dir
“Doctor amux”amux runner doctor --all (read-only)
“Teardown this worktree”two-step runner teardown plan + fresh digest
“Delegate work”authenticated native Amp creation on the exact executor/workdir
“/amux health”skill-only · read-only responsiveness check
“/amux sprawl”skill-only · coordinated native child threads

A binary, Amp CLI,
and tmux.

The checksum-verifying installer supports Linux and macOS arm64/amd64 and installs to ~/.local/bin/amux. Homebrew and other package-manager installs must remain owned and updated by that manager.

See the README for pinned releases, Homebrew, source builds, and update ownership.

install
$ curl -fsSL https://amux.zainf.dev/install.sh | sh

$ amux version
$ amux install doctor
$ amux update

# Homebrew owns Homebrew installs
$ brew install zainfathoni/tap/amux
$ brew upgrade amux
