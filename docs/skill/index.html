/amux

The core skill operates retained machine-local runners and routes new delegated work to native Amp child threads. It has no worker or legacy coordination route.

Install

npx skills add zainfathoni/amux --skill amux --global

Optional provider skills are installed separately with --skill amux-tycho, --skill amux-claude, or --skill amux-pi.

For a clean local checkout, the installer supports opt-in links without updating the checkout:

AMUX_REPO="$HOME/Code/GitHub/zainfathoni/amux"
git -C "$AMUX_REPO" pull --ff-only origin main
curl -fsSL https://amux.zainf.dev/install.sh | AMUX_SKILLS_SOURCE="$AMUX_REPO" sh

Terminology

  • Runner: a machine-local amp --no-tui process identified by canonical workdir.
  • Workspace: a same-named tmux session grouping runners.
  • Native child: an Amp thread created and coordinated through Amp, never enrolled in Amux lifecycle state.

Trigger routing

  • Pin this runner: amux runner pin --workspace <name> --workdir <path>.
  • Restore my workspace: amux launch --workspace <name>.
  • Park it: amux runner park --current or an exact workdir.
  • Doctor amux: amux runner doctor --all.
  • Spawn/delegate work: native Amp create_thread, not Amux spawn/adoption.

Skill-only workflows

/amux health performs read-only runner diagnostics. /amux sprawl creates independent native Amp children only. /amux sweep is the protected #360 read-only inventory and requires a separate exact owner authorization; loading the skill does not authorize it.

Removed surfaces

Worker, spawn, shelf, teardown, group, worker-report, callback, deadline, and finish commands are removed. Historical stores are inert and must not be migrated, rewritten, drained, or deleted. /amux-tycho remains a distinct explicit-only receipt bridge.

Safety

  • Use long selectors and current contextual help.
  • Use --dry-run before mutation and --json for parsing.
  • Runner row deletion fails closed without authoritative process/catalog absence evidence.
  • Runner commands never own remote Amp threads.
